# Real Copy Trade — locked preparation workspace

The main stock dashboard sidebar opens a native Real Copy Trade section (`/#real-copy`). It is a Solana copy workspace, not a stock copier. Its concise layout includes Phantom ownership linking, the shared paper playbook and roster, explicitly labeled PAPER performance and signal previews. Live positions/trades are empty and live P/L is unknown, never copied from paper profits.

`GET /real-copy/status` reads the canonical copy-paper state on each request. All current copy settings except paper enabled/funding are included, with entry rules, roster, discovery state and recorded results. A deterministic SHA-256 blueprint digest identifies the exact roster/rules preview; source cycle and settings revision distinguish live synchronization from historical proof. Future paper configuration fields flow through this read projection unless they are excluded funding/enabled fields. No separate adaptive copy-strategy learner exists today; the UI explicitly says so. General automatic meme-bot learning is a different strategy and is not silently applied to the copy engine. No paper cash, open holdings or historical fills become live account assets.

The frontend refreshes visible data every 15 seconds. A Phantom extension or Phantom mobile in-app browser is required to connect. The owner approves a clear off-chain link message, never a transaction or token delegation. `POST /real-copy/challenge` creates one current five-minute nonce bound to the wallet, origin and wallet-record revision. `/verify` checks a 64-byte Ed25519 signature over that exact UTF-8 message against the 32-byte decoded Solana key. Under one transaction it rejects expired, replayed, superseded, wrong-origin and stale-revision challenges and persists the public address/verification timestamp. Account switching invalidates an in-flight browser proof. `/unlink` clears the verified address and pending challenges. Saving a manually typed address in the old profile does not establish this proof. The proof is ownership evidence only, not ongoing browser connectivity or spending authority. No seed phrase, private key, transaction signing, balance sweep or delegation is accepted.

All APIs require the existing owner session; mutations also require the strict existing same-origin policy, JSON content type and exact bodies. Status is no-store. The backend has **no live execution implementation**. `/real-copy/start` always returns HTTP 423, including for a verified wallet or direct API request; source PAPER enabled=true cannot override it. The Start control is disabled for the same reason. A later live release requires a separately implemented execution/authorization path and explicit owner activation; this release does not claim that a public-wallet link makes unattended trading ready to launch.

Backend tests verify cryptographic ownership, replay/expiry/origin/revision protection, canonical sync, read-only isolation and the unconditional execution lock. Desktop/mobile browser tests verify layout, paper-only labels, connect/sign-message/unlink/decline/account-switch flows, synchronization and absence of transaction signing/submission.

## Trusted Phantom sessions and live readiness

The real workspace and meme profile use the shared `phantom-session.js` connection helper. After refresh, `connect({onlyIfTrusted:true})` silently restores an existing Phantom permission; no ownership message or transaction is signed during restoration. A matching persisted, verified wallet can reconnect manually without repeating its ownership proof. A different selected account is shown explicitly and cannot silently replace the saved proof. Locked/unavailable wallets retain their saved link. The profile restores only connection status, preserving saved/unsaved fields. Explicit unlink/disconnect stores only a no-auto-connect flag; reconnecting explicitly clears it. No credentials or signing authority are stored in browser storage.

Real-copy health distinguishes saved ownership, this browser's Phantom session, current source monitoring, live executor and unattended signing authority. A healthy paper feed never makes live readiness green. This release remains **Setup required** because the live executor and unattended signer do not exist. Page status failures turn red immediately; missing successful responses turn amber after 30 seconds and red after 60. Source freshness expires between polls; a clock watchdog never refreshes the successful-response timestamp. Trading stays locked server-side as well as in the UI.

Unattended real copying is a separate execution project: it requires an isolated trading wallet or a constrained signer, explicit capital/trade/loss limits, real quotes and fee/slippage checks, durable signed-transaction reconciliation and an exit worker independent of the browser. A wallet-link message is not that authorization. No real funds, delegation or transactions are handled in this update.

## Wallet-funded buy sizing

Real Copy Trade has independent owner settings: fixed USD per coin or a percentage (0–100] of available native SOL after an adjustable SOL fee buffer. No live buy amount is silently inherited from the paper account; the initial amount is unset. Settings are saved with compare-and-swap revisions and never enable live execution or change paper settings. The budget follows the saved, ownership-verified Phantom public address.

`GET /real-copy/balance` reads confirmed native SOL with `getBalance`, bounded by the shared read-only RPC rate limiter and a 30-second wallet-specific cache. A positive USD reference requires an exact wrapped-SOL base token, a stablecoin quote, positive liquidity and activity in the past five minutes. Quotes and balances expire after 45 seconds, including between frontend polls. RPC failures drop the previous balance; missing dollar quotes keep SOL visible but block fixed-dollar previews. Fixed buys above available funds show insufficient funds instead of shrinking the order. Percentage amounts round down to lamports; fixed-dollar requirements round up. Existing SPL coins, WSOL and stablecoins do not count as spendable native SOL.

This is a funding preview, not an admission or reservation ledger. The future executor must reread funds and price, account for pending commitments and actual fees/rent/slippage, and reconcile signed transactions before any live submission. No balance preview or settings save authorizes a trade.
